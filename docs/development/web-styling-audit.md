# Web styling audit

## Scope and evidence

This audit covers all 33 public families exported by [the web entry](../../src/index.web.ts), including the nonvisual HeroUIProvider. It compares the public adapters and typed `webProps`, owned web primitives and variant maps, [shared CSS](../../styles/shared/components/index.css), and [web overrides](../../styles/web-only.css) with the pinned HeroUI React 3.2.6 [component styles](../../upstream/heroui-react/packages/styles/components/index.css). Findings describe source-level gaps as of 2026-10-29, after the Checkbox animation repair. Browser rendering, interaction, accessibility, and native compilation were not checked.

The example already imports the package stylesheet and configures Uniwind to process it. Both the unified and web stylesheet entries load the web overrides. The recurring problem is incomplete mapping of HeroUI React CSS onto Native-derived shared classes and React Aria state attributes. An animation provider or an extra consumer configuration setting will not supply those missing rules. Importing upstream CSS verbatim will also miss renamed local slots.

“Missing” below means a supported state, variant, or component feature has no corresponding styling, or is replaced by a different effect. “Partial” means base styling exists but upstream layout, state handling, or motion is incomplete. “Present” means no specific missing rule was identified for the supported public surface; it does not mean identical pixels or complete runtime verification. Shared typography, radii, spacing, and colors intentionally differ from the React baseline in places and are not automatically defects.

## Prioritized findings

### 1. Supported props with missing visual behavior

- **Tabs:** [variant map](../../src/styles/web/components/tabs/tabs.styles.ts) emits `tabs--secondary`, `tabs--align-start`, `tabs--align-end`, and list-container/scroller/scroll-button classes. None have local component rules. The public adapter always composes ListContainer, so its unstyled overflow controls are on the normal rendering path. [React styles](../../upstream/heroui-react/packages/styles/components/tabs.css) define their positioning, default hiding, scroll-state visibility, vertical layout, secondary underline, and `translate`/width/height indicator transitions. Current overrides always use the primary pill styling. Restore these rules using `tabs__root` and `tabs__trigger` in place of React's root/tab names.
- **ScrollShadow:** [primitive](../../src/primitives/web/components/scroll-shadow/scroll-shadow.tsx) sets orientation, mode, size, and scroll-state attributes; [variant map](../../src/styles/web/components/scroll-shadow/scroll-shadow.styles.ts) emits fade, orientation, and hide-scrollbar classes. Current web CSS only adds `overflow: auto` and a thin scrollbar. [React styles](../../upstream/heroui-react/packages/styles/components/scroll-shadow.css) use those attributes to mask overflowing edges and preserve the scrollbar. Restore the attribute-driven masks and scrollbar hiding first; scroll-driven progressive enhancement can follow without replacing the hook's manual/disabled behavior. Tabs also depends on this primitive.
- **Switch:** [variant map](../../src/styles/web/components/switch/switch.styles.ts) supports `sm`, `md`, and `lg` through public `webProps.size`, while shared CSS fixes the control at 48×24px and thumb at 28×20px. Current selected positioning jumps directly to an 18px inset. [React styles](../../upstream/heroui-react/packages/styles/components/switch.css) define size-specific track/thumb dimensions and a 300ms margin transition, checked colors, disabled combinations, and track focus rings. Restore those rules on the renamed `switch-field` and `switch__root` slots.
- **RadioGroup:** [group variant map](../../src/styles/web/components/radio-group/radio-group.styles.ts) emits secondary, and the React Aria group accepts orientation through public `webProps`; current CSS keeps the group in a column. Shared Native radio variants are not emitted by the web primitive. Current selection only reveals a static accent dot in a field-colored control. [React group](../../upstream/heroui-react/packages/styles/components/radio-group.css) and [radio styles](../../upstream/heroui-react/packages/styles/components/radio.css) define orientation, secondary backgrounds, accent selection, a shrinking foreground dot, press/hover feedback, and control focus. Map those states onto `radio__root` and the empty indicator.
- **Avatar:** [variant map](../../src/styles/web/components/avatar/avatar.styles.ts) emits `avatar--soft`; [shared CSS](../../styles/shared/components/avatar.css) instead expects Native compound classes such as `avatar__root--variant-soft--color-accent`, which the web map never emits. [React styles](../../upstream/heroui-react/packages/styles/components/avatar.css) color the fallback background by soft variant and status. Add matching web selectors or correct the web variant map; do not infer that fallback foreground color alone implements the variant.
- **TagGroup:** [tag map](../../src/styles/web/components/tag/tag.styles.ts) always includes `tag-group__tag--variant-default tag-group__tag--size-md`, then adds `tag--sm/lg/surface`. Local CSS never handles those modifiers. Public item `webProps.size` and `webProps.variant`, including values inherited from the group's web props, therefore retain the default shared dimensions/background. [React tag styles](../../upstream/heroui-react/packages/styles/components/tag.css) also provide item hover, disabled opacity, soft selected colors, and transitions. Preserve the prior remove-button repair while correcting item styles.
- **InputOTP:** [variant map](../../src/styles/web/components/input-otp/input-otp.styles.ts) emits root modifiers, while [shared slot CSS](../../styles/shared/components/input-otp.css) expects per-slot Native modifiers. [The web primitive](../../src/primitives/web/components/input-otp/input-otp.tsx) already emits `data-active`, `data-filled`, `data-disabled`, and `data-invalid`. Current browser rules handle active and invalid borders but omit disabled slot appearance and filled feedback. [React styles](../../upstream/heroui-react/packages/styles/components/input-otp.css) also animate new values and distinguish primary/secondary backgrounds. Add root-to-slot variant rules and attribute-based state styling.
- **Select:** [web map](../../src/styles/web/components/select/select.styles.ts) emits primary/secondary/full-width classes with no matching local rules. [Primitive](../../src/primitives/web/components/select/select.tsx) retains the React Aria states, while current CSS gives every trigger width 100% and a static field background. [React styles](../../upstream/heroui-react/packages/styles/components/select.css) define the root layout, placeholder color, hover/focus/open/invalid states, secondary field behavior, list sizing, and overlay animation. Scope fixes to public Trigger, Value, Content, and Item; the internal ClearButton is not an exported adapter part.
- **Separator:** [web map](../../src/styles/web/components/separator/separator.styles.ts) emits `separator--secondary` and `separator--tertiary` through public `webProps.variant`, but current CSS always applies `--color-separator`. [React CSS](../../upstream/heroui-react/packages/styles/components/separator.css) provides distinct secondary and tertiary colors. Add matching rules using verified shared token equivalents; horizontal and vertical orientation rules already match the web primitive.

### 2. Missing motion and interaction states

- **Accordion:** [primitive](../../src/primitives/web/components/accordion/accordion.tsx) emits expanded state, `data-hide-separator`, and `accordion__body-inner`; current CSS only rotates the icon instantly and hides a panel by `data-inert`. [React CSS](../../upstream/heroui-react/packages/styles/components/accordion.css) consumes `--disclosure-panel-height` for a 200ms height/opacity transition and defines separators, body-inner styling, trigger hover/disabled treatment, and 250ms indicator motion. Restore these contracts without forcing `display: none` during an animated collapse.
- **Popover:** [primitive](../../src/primitives/web/components/popover/popover.tsx) retains React Aria enter/exit and placement state. Current CSS has no animation and rotates arrows only for bottom placement. [React CSS](../../upstream/heroui-react/packages/styles/components/popover.css) defines placement-specific entry translation, fade/scale, exit pointer-event suppression, all arrow rotations, and trigger states. Implement equivalent local keyframes and reduced-motion overrides or explicitly include the required animation utilities; adding a consumer plugin alone does not create the missing selectors.
- **Skeleton:** [variant map](../../src/styles/web/components/skeleton/skeleton.styles.ts) correctly selects `shimmer`, `pulse`, or `none`. Current CSS assigns the same pulse animation to both animated variants. [React CSS](../../upstream/heroui-react/packages/styles/components/skeleton.css) uses a translating gradient pseudo-element for shimmer. Restore a separate shimmer effect with reduced-motion handling. The adapter omits loading children, so upstream's nested-skeleton synchronization rules are not directly reachable through its loading composition.
- **Slider:** [primitive](../../src/primitives/web/components/slider/slider.tsx) supplies label/output/track slots, orientation, dragging state, and `data-fill-start/end`. Current CSS uses a simple flex column, 6px track, and 24px accent thumb, without a distinct inner knob or drag feedback. [React CSS](../../upstream/heroui-react/packages/styles/components/slider.css) defines the label/output grid, horizontal/vertical track borders, inner thumb pseudo-element, drag cursor/scale, and transitions. Restore this geometry together so the thumb and fill use the same coordinate space. Marks are internal and not part of the public adapter audit.
- **Toast:** [primitive](../../src/primitives/web/components/toast/toast.tsx) computes `--front-height`, `--toast-height`, collapsed/expanded offsets, and frontmost/expanded/entering/exiting states. Current rules consume offsets and scale, but ignore stack heights and show back-toast content. [React CSS](../../upstream/heroui-react/packages/styles/components/toast.css) defines collapsed-content hiding, unified stack heights, expanded gap hit areas, enter movement, close-button visibility, and variant indicator colors. Restore the default `useToast()` path first. Additional internal provider placements and promise-swapped indicator animation are separate from the public manager, which does not expose those options.

### 3. Field and text styling gaps

- **Input:** [shared CSS](../../styles/shared/components/input.css) sets minimum height, horizontal padding, text, border, and backgrounds, but no web field shadow, vertical padding, responsive font size, hover/focus background changes, or transitions. The current browser focus outline only covers `data-focus-visible`. [React CSS](../../upstream/heroui-react/packages/styles/components/input.css) styles native focus and `data-focused` as well. Restore browser-specific behavior without changing Native input dimensions.
- **TextArea, InputGroup, SearchField:** Their basic web shells and repaired adornment layout are present in [web overrides](../../styles/web-only.css). [React TextArea](../../upstream/heroui-react/packages/styles/components/textarea.css), [InputGroup](../../upstream/heroui-react/packages/styles/components/input-group.css), and [SearchField](../../upstream/heroui-react/packages/styles/components/search-field.css) have state transitions and secondary-specific hover/focus colors. Current secondary styles set only the resting background; generic focus/hover then switches to primary field tokens. InputGroup/SearchField also omit upstream's group-level autofill treatment. Their width defaults do not distinguish the full-width modifiers. Do not classify InputGroup.TextArea as a public gap: that part is not exported by this adapter.
- **TextField and SearchField:** [React TextField CSS](../../upstream/heroui-react/packages/styles/components/textfield.css) and React SearchField CSS hide descriptions during invalid state. That handling is absent locally. TextField's full-width utility applies only to the root; the upstream propagation to input/textarea slots is missing. Decide the desired help-text behavior explicitly before restoring it.
- **Label:** [local map](../../src/styles/web/components/label/label.styles.ts) and shared CSS cover explicit label flags; web CSS propagates state only for TextField. [React CSS](../../upstream/heroui-react/packages/styles/components/label.css) also derives invalid, disabled, and required appearance from other field parents, with exclusions for individual radio/checkbox options. Restore scoped parent-state rules and avoid duplicate asterisks.
- **Description and FieldError:** [shared description](../../styles/shared/components/description.css) and [shared error CSS](../../styles/shared/components/field-error.css) style text but omit [React description wrapping](../../upstream/heroui-react/packages/styles/components/description.css) and [React error visibility transitions](../../upstream/heroui-react/packages/styles/components/field-error.css). The local error primitive already sets `data-visible`. Keep toggle-field error exceptions and actual mount/unmount behavior in mind when adding transitions; CSS presence alone does not prove an exit animation runs.
- **Card:** [web map](../../src/styles/web/components/card/card.styles.ts) maps Content to `flex-1`, losing the flex-column/gap supplied by [React Card CSS](../../upstream/heroui-react/packages/styles/components/card.css). Root uses shared Surface, whose `overflow: hidden` differs from the React Card's `overflow-visible`. Preserve surface variants while deciding whether web Card needs a distinct root selector and overflow policy.
- **Alert:** [web map](../../src/styles/web/components/alert/alert.styles.ts) emits status only on the root. Current overrides color titles, while [React CSS](../../upstream/heroui-react/packages/styles/components/alert.css) colors indicators too and supplies flex centering, padding, and default-icon sizing. Native title/indicator conventions do not supply these missing web rules.

## Implementation and verification order

1. Correct supported props that currently lack effects: Tabs, ScrollShadow, Switch, RadioGroup, Avatar, TagGroup, InputOTP, Select, and Separator. Prefer public state/slot selectors or complete web variant mappings over importing unmatched upstream class names.
2. Restore geometry and motion together for Accordion, Popover, Slider, Skeleton, and Toast; honor reduced motion and disabled states and preserve overlay exit lifecycles.
3. Complete field state transitions, secondary tokens, Label inheritance, wrapping, and Card/Alert layout. Keep shared theme differences explicit rather than replacing the entire Native-derived design.
4. Add stylesheet compilation assertions for the emitted selectors and meaningful non-rendering prop/class mappings. Check the unified and web entries, both platform types, package build, and existing gallery coverage when implementation changes.
5. Browser appearance and animation timing require explicit runtime verification. No preview server, browser automation, device run, or native build was used for this audit.
